Para quem está começando em TI, o GitHub costuma ser o primeiro lugar que um recrutador ou colega olha para
entender o que você realmente sabe fazer. Um portfólio bem organizado vale mais do que dezenas de projetos
inacabados e sem explicação.

## Prefira poucos projetos bem documentados

<Callout type="info">
Três projetos completos, funcionando e bem explicados comunicam muito mais do que quinze repositórios vazios ou
com apenas um arquivo solto. Qualidade sobre quantidade, especialmente no início.
</Callout>

## O que todo repositório de portfólio deveria ter

1. **Um README claro** — a primeira coisa que qualquer pessoa vê ao abrir o repositório.
2. **Código organizado** — pastas com nomes claros, sem arquivos de teste ou rascunhos soltos na raiz.
3. **Instruções de instalação e uso** — como rodar o projeto localmente, passo a passo.
4. **Commits com histórico coerente** — mensagens claras, não um único commit gigante chamado "projeto final".

## Estrutura de um bom README

```markdown
# Nome do Projeto

Uma frase explicando o que o projeto faz.

## Tecnologias usadas
- Python
- FastAPI
- PostgreSQL

## Como rodar localmente
1. Clone o repositório: `git clone <url>`
2. Instale as dependências: `pip install -r requirements.txt`
3. Rode o projeto: `uvicorn main:app --reload`

## O que este projeto demonstra
Breve explicação do problema resolvido e das decisões técnicas tomadas.
```

<Callout type="atencao">
Não invente funcionalidades, resultados ou métricas que o projeto não tem de verdade. Um README honesto sobre o
que o projeto realmente faz — mesmo que simples — passa mais confiança do que um exagero que não se sustenta em
uma entrevista técnica.
</Callout>

## Organizando o perfil do GitHub como um todo

- **Foto e bio** — algo simples, dizendo em que área você está estudando ou atuando.
- **Repositórios fixados (pinned)** — escolha os 3-6 melhores projetos para aparecerem em destaque no seu perfil.
- **README do perfil** — um repositório especial (com o mesmo nome do seu usuário) que vira a página inicial do
  seu perfil no GitHub, com uma breve apresentação sua.

## Um projeto vale mais que mil linhas de currículo

Um projeto de portfólio bem feito — por exemplo, uma API simples com FastAPI e banco de dados, ou um script de
automação bem documentado — demonstra na prática habilidades que um currículo só descreve. Vale revisar os
artigos de [Back-End](/backend) e [FastAPI](/fastapi) desta trilha para ideias de projetos completos.

## Perguntas frequentes

**Preciso ter muitos repositórios para parecer experiente?**
Não — o oposto costuma ser verdade. Poucos projetos completos e bem explicados passam mais credibilidade do que
muitos incompletos.

**Posso usar projetos de curso no meu portfólio?**
Sim, desde que você entenda profundamente o que fez e consiga explicar as decisões tomadas — inclusive adaptando
ou expandindo o projeto original com algo seu.

## Resumo

Um bom portfólio no GitHub prioriza qualidade: poucos projetos, bem documentados, com README claro e instruções de
uso. O perfil como um todo — foto, bio e repositórios fixados — também comunica profissionalismo antes mesmo de
alguém abrir o código.
